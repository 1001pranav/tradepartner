# M6: ML pipeline and model registry, done

## What exists
- Features v1 (`fs1`, `features/`): price/volume (returns, volatility, ATR, SMA distances, RSI, 52-week distance, volume z-score, gap, close location, 12-1 momentum), cross-sectional turnover rank, market regime (Nifty vs 200-day SMA, VIX, breadth), index- and sector-relative returns, calendar, and the news features from M5. Every row at date `t` uses only bars dated <= t (tested by truncating the future and comparing).
- Labels (`features/labels.py`): swing `y = 1` if the 5-day forward return from the **next open** beats Nifty by round-trip cost + 0.5% (cost comes from `config/costs.yaml`); positional is the cross-sectional rank of the 60-day forward excess return. The last `horizon` rows have NaN labels.
- `models/cv.py`: expanding walk-forward with an embargo equal to the label horizon and purge in one rule (a training label window must end strictly before the test window starts); property-tested.
- `models/train.py`: LightGBM, seeded and deterministic; Optuna (hard cap 50 trials) runs **inside** each training fold on a time-ordered inner split.
- `models/evaluate.py`: promotion gate, all seven checks (Sharpe >= baseline + 0.3, drawdown <= 1.2x baseline, >= 100 trades, >= 60% positive windows, positive with doubled slippage, no feature above 40% gain share, human approval which is **always pending**). The evaluator is a vectorised simulation of the walk-forward predictions; the event-driven backtester remains the final word.
- `models/registry.py` + `models/approval.py`: statuses candidate -> shadow -> approved -> retired. Approval needs the gate, 14 days in shadow, a passed shadow comparison and the user. The previous model is kept for rollback. **Only `cli` and `ui` can import `approval` (import-linter).** Training can only ever create a `candidate`.
- `models/drift.py`: PSI on the top 10 features (> 0.25 flags) and rolling-60 Brier score against the training value.
- `models/pipeline.py`: trains a price-only variant and (if LLM-era news history exists) a with-news variant, evaluates the news variant only on LLM-valid rows, reports the period in which LLM features were actually tested, and picks with-news only if it passes and beats price-only on the same rows.
- CLI: `train`, `models list|shadow|approve|rollback`. UI: Strategies and Models page.

## Acceptance
- A `swing_v1` walk-forward report is produced with and without news features (`tests/unit/test_pipeline_m6.py`, synthetic data with a planted momentum effect; the model learns it, AUC > 0.5 out of sample).
- The gate is evaluated automatically; nothing is auto-approved (tests assert `approved_by is None` after training and that the CLI and UI refuse to skip shadow).

## Caveats
- The gate numbers are only as good as the data. With synthetic data they prove the mechanics, not an edge. Run `tradepartner data backfill` then `tradepartner train --strategy swing_v1` on your 10-year history.
- A full backtest of a model on dates before its `train_end` is in-sample; judge models by the walk-forward report.
- LLM-derived features have very little history until news collection has run for a while, so the price-only model will normally be chosen at first.
- Migration 0004 adds `signal_outcomes` (append-only).
