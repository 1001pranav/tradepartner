# M8: AUTO execution via Kite, code complete; LIVE ACCEPTANCE IS YOURS

**No real order was placed while building this** (CLAUDE.md rule 10). Everything below was tested against a recording fake Kite API. Kite has no sandbox, so the final acceptance must be done by you with 1-share orders. **Do not enable AUTO or raise any size until you have signed off at the bottom of this file.**

## What exists
- `execution/kite.py` `KiteBroker`: `place_order` accepts only a risk-engine-minted `ApprovedOrder`; NSE cash equity only (CNC/MIS); limit orders by default; market orders always carry market protection; 1 order/second token bucket; tags <= 20 chars; **a tag is never placed twice, even after a crash**; static-IP rejections are recognised and alerted.
- GTT OCO protection (`place_gtt_oco`, `modify_gtt_oco`, `list_gtts`, `delete_gtt`): SELL-only, two legs; the stop leg sells as a limit 1% below its trigger so it can fill.
- `execution/protective.py` `ProtectiveManager`: every open bot CNC position must have a correct GTT. Checked every 5 minutes and after each fill. AUTO recreates or resizes it; MANUAL only alerts; orphan GTTs are reported, never auto-deleted; a price already through the stop is flagged "BREACHED" instead of placing an impossible GTT. Results go to the audit log and the Positions page.
- `Router.approve_and_place` (MANUAL `api_approve`): your click re-runs the risk engine on fresh data (stale or no-longer-safe orders are refused, and the refusal is recorded) and never places a proposal twice.
- AUTO-only limits, the unlock flow, kill switch and halts were built in M3; `appctx.py` is the composition root. `broker: paper` stays the default; `broker: kite` never silently falls back to paper.
- `tradepartner live-test entry|protect|cancel SYMBOL --i-understand-this-places-real-orders`: 1-share orders only (hard-coded cap, persisted with the proposal, re-checked before placement), full risk engine, typed `PLACE 1 SHARE` confirmation.
- Jobs `poll_fills` (30 s) and `protective_check` (5 min).

## A bug the tests caught
While writing the live-test tests, an `api_approve` re-check rebuilt the proposal without its size cap, so a "1-share" test sized to **72 shares**. The post-placement guard cancelled it, but it should never be placed. Fixed: the cap is stored on the proposal (migration 0006) and re-applied; `place_entry` refuses any proposal that is not a capped 1-share test before calling the broker.

## Before you run the live acceptance
1. Register a static IP with Zerodha (see `ops/README.md`) **[VERIFY the current process]**.
2. In `config/app.yaml` set `broker: kite` and `manual_execution: api_approve`; set `capital_base_inr` in `config/risk.yaml`.
3. `tradepartner login`, then during market hours (09:20 to 15:00 IST), on a very liquid stock:

| # | Step | Command | Expected |
|---|---|---|---|
| 1 | Entry | `tradepartner live-test entry INFY --i-understand-this-places-real-orders` | risk decision `shown`, then after typing `PLACE 1 SHARE` one 1-share LIMIT order tagged `tp-<id>` |
| 2 | Fill and ledger | wait for the fill, then `tradepartner sync` | one fill, origin `bot_manual_api`, charges within about Rs 1 of the contract note |
| 3 | GTT | `tradepartner live-test protect INFY --i-understand-this-places-real-orders` | status CREATED; the GTT appears in Kite; Positions page shows a green status |
| 4 | Cancel | enter again with a limit away from the market, then `live-test cancel <order_id> ...` | order cancelled in Kite |
| 5 | Kill | `tradepartner kill` | global OFF, open entry orders cancelled, CNC and its GTT untouched |
| 6 | Reconcile | `tradepartner sync` | no position mismatch |
