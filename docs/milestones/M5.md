# M5: News and LLM analyst, done (live acceptance items pending on your machine)

## What exists
- Sources (`news/sources/`): RSS/Atom (defusedxml, so hostile XML cannot expand), NSE announcements + results calendar, BSE announcements, GDELT (historical backfill, titles only). Each implements `fetch(since)`; failures are logged and skipped; rate limiting is injected.
- `news/ingest.py`: URL and content-hash dedupe; near-duplicate clustering (title similarity >= 0.85 within 24 h, **keeping the earliest**); `published_at` falls back to `fetched_at` with `published_at_estimated` set, and impossible future dates are treated the same way. `news_raw` is append-only (DB trigger).
- `news/entity_link.py`: alias table from instrument names, tickers, ISINs and `config/universe/aliases.csv`; title before body; ambiguous aliases ("tata", "adani") are never guessed. The LLM must choose from the candidate list or answer null, and a symbol outside the list is rejected.
- `llm/client.py`: Ollama wrapper with JSON-schema constrained output, temperature 0, fixed seed, `num_ctx` 4096, retries with backoff. One retry on invalid output, then the article is discarded (a zero-weight marker row is stored so it is not retried forever). `llm/prompts/` holds versioned templates; model name, digest and prompt version are stored with every score.
- `news/analyst.py`: scores pending (article, symbol) pairs, universe/held/exchange items first; honours the 08:00-09:00 time budget; reports schema-valid rate and throughput.
- `features/news.py`: count, weighted sentiment, days since a material event, event-type counts and "results in next N days". Point-in-time: live mode requires `max(published_at, fetched_at) <= as_of`; backtest mode uses `published_at + 15 min` (fetch time of a later backfill is irrelevant). **LLM knowledge-cutoff rule**: before `knowledge_cutoff + 90 days` all news features are NaN and `llm_features_valid = 0`.
- CLI: `news fetch | score | stats | results-calendar | backfill`.

## Acceptance
- Leakage tests (`tests/unit/test_leakage.py`): future-dated, later-fetched and post-cutoff items never move a feature.
- Schema validation, one-retry-then-discard, ordering, time budget and Ollama outage handling are tested against a mock Ollama.
